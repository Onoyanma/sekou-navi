# 時間計測の実験手順

**目的**：施工ナビを使うと、型番を確認して施工説明書にたどり着くまでの時間が、従来のやり方と比べてどれだけ変わるかを測る。

モデルの精度（Top-1 など）は「アプリがどれだけ正しいか」の指標で、**使う人がどれだけ得をするか**は別に測る必要がある。この実験は、そのための最小の設計。

## 1. 準備（実験の 1〜2 日前）

### 1-1. 商品を 10 個選ぶ
- 型番ラベルが付いていて、**メーカーの公式サイトに施工（取扱）説明書がある**もの。
- **これまでの評価用写真とは別の商品**にする（実験用の写真は、そのまま「未使用の評価データ」としても使える）。
- 種類を散らす（水回り・照明・家電・電設資材など）。同じメーカーに偏らない。
- 各商品に `P01`〜`P10` の番号を振り、**正解（型番と、説明書の URL）を先に控えておく**。

### 1-2. 正解を作る
`record_sheet.csv` とは別に、自分用のメモに次を書く。

| 番号 | 型番 | 説明書の URL（正解） |
|---|---|---|
| P01 | … | … |

「説明書を開いた」の判定は、**型番が合っている説明書のページ（PDF でも商品ページでも可）が表示されたこと**とする。

### 1-3. 施工ナビの状態を揃える
- 10 個のうち、**5 個は登録済み、5 個は未登録**にする（未登録のときの導線も測るため）。
- 登録は、実験の前に済ませておく（実験中に登録しない）。登録済みの商品は、ラベルとは別の角度の写真で登録しておくと公平。
- 通信環境（Wi-Fi か回線か）は、全員同じにして記録する。

## 2. 条件

| | 方法 A（従来） | 方法 B（施工ナビ） |
|---|---|---|
| 使う道具 | スマホとブラウザ（Google 検索・Google レンズなど、**普段のやり方で自由に**） | 施工ナビ |
| 始まり | 実物のラベルを見て「開始」と言った瞬間 | 同じ |
| 終わり | 正しい説明書が表示された瞬間 | 同じ |
| 制限時間 | 3 分（超えたら失敗として記録） | 同じ |

## 3. 割り当て（順序の偏りを消す）

- 参加者は 3〜5 人（自分だけだと慣れの偏りが大きいので、**自分以外を最低 2 人**）。
- **1 人が全部の商品を 2 回測るのではなく、1 商品につき 1 回だけ**測る（同じ商品を 2 回やると、2 回目は答えを知っているので速くなる）。
- 参加者ごとに、方法と商品の組み合わせを入れ替える。

| 参加者 | 前半 5 個の方法 | 後半 5 個の方法 | 商品の割り当て |
|---|---|---|---|
| 1 人目 | A | B | 前半 P01〜P05、後半 P06〜P10 |
| 2 人目 | B | A | 前半 P01〜P05、後半 P06〜P10 |
| 3 人目 | A | B | 前半 P06〜P10、後半 P01〜P05 |
| 4 人目 | B | A | 前半 P06〜P10、後半 P01〜P05 |

- 本番の前に、実験に使わない商品で **1 回だけ練習**してもらう（道具の使い方で迷う時間を除くため）。

## 4. 当日の進め方

1. 目的を説明する：「アプリを試験しているのであって、あなたの能力を測っているのではありません」。
2. 練習を 1 回行う。
3. 商品を 1 つずつ渡し、「開始」の合図で**ストップウォッチ**を押す。
4. 正しい説明書が表示されたら止めて、`record_sheet.csv` に記録する。
5. **途中で助け舟を出さない。** 手が止まった場所、迷った画面、つぶやきをメモする（これが一番の収穫）。
6. 全部終わったら、最後に次の 3 つを聞く。
   - 普段、型番から説明書を探すとき、どうしていますか。何分くらいかかりますか。
   - 施工ナビで、どこで手が止まりましたか。
   - これがあれば、実際に使いますか。使わないなら、何があれば使いますか。
7. 次の 3 つを 1〜5 で答えてもらう（1 = そう思わない、5 = そう思う）。
   - 使い方がすぐ分かった
   - 結果を信用できた
   - 現場で使えそうだ

## 5. 記録する項目（`record_sheet.csv`）

| 列 | 内容 |
|---|---|
| participant | 参加者の ID（`U1`、`U2`…。名前は書かない） |
| item | 商品の番号（`P01`…） |
| method | `A`（従来）または `B`（施工ナビ） |
| registered | 方法 B のとき、その商品が登録済みなら `yes`、未登録なら `no`（A は空欄） |
| seconds | かかった秒数 |
| success | 正しい説明書にたどり着けたら `1`、失敗・時間切れは `0` |
| notes | 手が止まった場所、つぶやき、読み取りの失敗など |

## 6. 集計

```bash
cd backend
python -m evaluation.analyze_time_experiment ../docs/experiment/record_sheet.csv
```

方法ごとの件数・中央値・平均・最小・最大・成功率と、方法 B の登録済み／未登録の内訳が表示される。

- **人数が少ないので、有意差の検定はしない。** 中央値と幅を並べて、「だいたいどれくらい違うか」を報告する。
- 失敗（時間切れ）は、秒数を 180 秒として別に数える（平均が不当に良く見えるのを防ぐため）。

## 7. 結果の書き方（READMEや面接で）

- 良い例：「5 人・各 5 商品（計 25 回ずつ）で測り、説明書にたどり着くまでの中央値が ○ 秒から ○ 秒になった。ただし参加者は少なく、条件の統制も限られる」
- **悪い結果も、そのまま書く。** 例えば「未登録の商品では、従来の方法と大差がなかった。原因は…」。原因を分析して次の改善につなげられれば、それが最も強い材料になる。

## 8. 注意

- 参加者の名前・写真・声は記録しない（ID だけ）。顔や自宅が写る場所での撮影は避ける。
- 自分だけで測った結果は、「自分は使い方を知っている」ため、施工ナビが有利になる。必ず他の人のデータと分けて報告する。
